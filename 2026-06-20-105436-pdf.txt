     План улучшения ООП в проекте kwork-bot-v2

     Context

     Проект представляет собой Telegram бота для управления диалогами на
     платформе Kwork с интеграцией GPT. Текущая архитектура нарушает несколько
     принципов ООП:
     - Single Responsibility Principle — KworkManager делает 6+ разных вещей
     - Типизация — ModelAdmin.get() возвращает T но может быть None; интеграции
     возвращают бесструктурные dict
     - Дублирование кода — загрузка файлов повторяется в двух местах
     - Отсутствие тестов — критическая проблема для production
     - Слабая обработка ошибок — broad except Exception повсюду
     - Недокументированность — основные методы не имеют docstring

     Цель

     Рефакторить проект согласно принципам ООП, повысить типизацию, добавить
     тесты и документацию.

     # Архитектура проекта kwork-bot-v2

     ## Компоненты

     ### KworkManager
     Оркестратор, управляющий основным потоком обработки диалогов.

     ### MessageProcessor (абстрактный)
     - AIMessageProcessor — обработка с помощью GPT
     - ManagerMessageProcessor — обработка менеджером

     ### FileService
     Работа с файлами: загрузка, парсинг, отправка в TG.

     ### TopicService
     Создание и управление топиками (форум-каналы) в Telegram.

     ### KworkAccount (integrations/kwork.py)
     API клиент для платформы Kwork.

     ### GPTHandler (integrations/openai.py)
     API клиент для OpenAI.

     ## Data Flow

     1. KworkManager.task() → получить диалоги
